# 备份原则
基础软件和大数据存储都很庞大，备份策略不同。其它目录是全量增删完全同步式备份多地，源删除备份也要删除。大数据存储是增量式备份，删除的文件备份时不删，变小的文件要告警，除非手工处理。基础软件运行时很庞大，只备份安装脚本，kdb的运行软件很小，可以备份。
# 使用程序与数据的原则
为了可移植性，永远不要使用写死的绝对路经。主要使用环境变量和软链接来使用目录。其中大数据存储的冷数据可能存储在还没有挂载的其它硬盘内，使用时临时挂载硬盘，如tick ，一分钟数据，这类大的冷数据会化大数据存储目录再次建立软链接的方式链接到挂载的硬盘的目录中。大数据存储目录中的各子目录从属于各金融业务部门，各金融业务部门会建立到大数据存储里子目录的软链接。
常更新的数据目录，要分当前目录和历史目录，平时只更新当前目录。
每个目录下的程序运行时产生的数据文件，小文件放自己的程序目录下一起随程序备份，有用的日志放mylab/log下，此目录不备份。没有用的日志全写到/tmp。
定期清理nohup.out   __pycache__ 等临时文件或目录，这些目录不备份，.git目录也不备份
